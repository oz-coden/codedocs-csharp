# Current limits

- The executable targets .NET 9. The analyzed project may target other frameworks when its SDK, workloads, and reference assemblies are installed. Roslyn is pinned to 4.14, with C# 13 support; newer language features require an explicit dependency upgrade.
- MSBuildWorkspace evaluates the installed SDK's selected configuration. Multi-target projects are represented as the workspace loads them; the CLI does not promise to enumerate and merge every framework/configuration combination. SDK-style C# projects are the primary tested input.
- Dependencies must be restored before analysis. The tool does not install SDKs, workloads, or missing packages.
- Generated files and source-generator output present in the compilation are included. Analyzers/source generators execute as part of workspace compilation. The tool is not a sandbox for untrusted projects.
- Inheritdoc handles cref, overridden members, base types, and interface implementations. XPath uses .NET XPath 1.0 and must select nodes; common `/summary/node()` paths address the contents of the member, while explicit `/member/...` paths address the member root. Scalar results, invalid expressions, empty results, and cycles are preserved with warnings. Parameter and type-parameter names are remapped by ordinal when their counts match; plain prose is never rewritten. Documentation inheritance does not emulate every vendor-specific XML extension.
- XML lists support bullets, numbering, and tables in HTML/Markdown. Unrecognized XML tags preserve textual contents but not arbitrary custom formatting; raw XML and structured nodes remain available in JSON. HTML markup supplied through documentation is escaped.
- Inherited members are grouped by declaring type and category. Details link to internal documented members when available. External base-member names remain plain text. Constructor inheritance is excluded.
- Displayed signatures are reconstructed from compiler symbols plus source modifier information. They retain API meaning, not original whitespace or aliases. Declaration headers and raw XML remain available in the semantic model. Assembly/module attributes are represented separately from type/member declarations where collected. Attributes on backing fields are associated with their property/event using the `field` target; backing-field implementation names are not exported as normal API members. Event field-target attribute display retains normalized source spelling, while bound types and values are stored separately.
- Explicit interface implementations are included for visible interfaces even when their declared accessibility is private. This exposes the implementation through its interface contract.
- Output paths must use a dedicated directory. The output transaction prevents ordinary partial updates but cannot guarantee uninterrupted reads or recovery from every power loss. The generator does not automatically publish or serve the output.
- JSON retains legacy display strings alongside structured type references, constants, constraints, XML nodes and inheritance provenance. Attribute enum values retain the declared enum type and numeric value rather than inferring a preferred enum-member spelling. JSON is available as an initial renderer; its schema is not yet declared stable. There is no MCP server, external renderer plugin protocol, extension-method reverse index, or source-repository link configuration.
